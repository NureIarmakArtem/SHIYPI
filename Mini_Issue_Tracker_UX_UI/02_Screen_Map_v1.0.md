3. Текстові User Flows за ключовими сценаріями
Створення та перегляд заявки: S-02-A (All Issues) -> клік Create Issue -> M-01 -> ввід Title + Description -> клік Create -> S-03 (нова заявка: Open, Not Set, Unassigned) -> клік Return to Issues List -> S-02-A.

Призначення та пріоритизація (Team Lead): S-02-A -> клік на ISS-006 -> S-03 -> вибір Assignee (Member A) + Apply -> вибір Priority (High) + Apply -> S-03 (оновлено).

Дозволені статусні переходи та повернення Resolved у роботу (Assignee): S-03 (ISS-003, Status = Resolved, Assignee = Member A) -> актор Member A обирає In Progress (повернення в роботу) або Closed (завершення) + Apply -> S-03 (Status оновлено). Якщо обрано Closed, при поверненні на S-02-B (Important Issues) заявка ISS-003 зникає з важливих.

Заборонена дія для неуповноваженого користувача: S-03 (ISS-003, Assignee = Member A) -> актор Team Lead (non-assignee) бачить активні контролі Assignee та Priority, але контрол Status має стан disabled (перехід заблоковано за AC-07.4).

4. Що НЕ слід додавати (Exclusions — 3 приклади типових функцій issue trackers)
Блок прикріплення файлів (Attachments / Dropzone): відкладено в Deferred (US-09).

Панель чи бейджі AI-рекомендацій категорії/пріоритету: відкладено у Future (SR-10, SR-11).

Чекбокси вибору рядків у таблиці (Bulk selection), пошук, фільтри за автором або кнопка Delete Issue: прямо заборонені BR-10 та Exclusions погодженого брифа.
